# Project audit — 2026-09-04

## Delivery status

KiliPicks is a functional Expo MVP, with a live catalog experience, search,
provider detail, saved providers, contact actions, analytics/observability,
video splash, category browsing, and clearly marked booking/auth scaffolding.
The existing progress log accurately records that production authentication,
appointments, payments, notifications, maps, reviews, and publishing remain
outside the delivered scope.

## Evidence checked

- `pnpm typecheck` and `pnpm lint` are documented as green in the current
  progress log; this audit adds an automated unit-test foundation.
- Catalog input is validated at the API boundary with Zod, including a typed
  error/reporting path for invalid responses.
- Contact actions normalize Kenyan numbers and reject non-HTTP web links.
- The working tree already had unrelated changes in `app.json` and `.claude/`;
  they were not altered by this work.

## Main risks before release

1. No real-device testing has verified video-splash timing, the search overlay,
   contact deep links, analytics delivery, or Sentry native behaviour.
2. The demo API remains a production dependency until a real backend domain,
   CORS policy, availability monitoring, and service ownership are supplied.
3. Auth and booking are intentionally non-functional UI boundaries; the phone
   capture flow needs approved privacy content before any production auth work.
4. Critical integration behaviour has no automated coverage yet: API fetch
   failures, cached/stale catalog behaviour, AsyncStorage saved state, routes,
   and native device flows.

## Test foundation added

`tests/` now covers unit-level phone normalization, safe contact-link building,
category and version utilities, and catalog schema acceptance/rejection. Run
`pnpm test` for a one-off run or `pnpm test:watch` during development.

## Recommended next steps

1. Run the app on a physical Android device/custom dev client and execute a
   short smoke-test checklist for the core flows.
2. Add mocked tests for catalog fetching/caching and saved-provider state.
3. Establish staging/production backend ownership and complete the EAS/Play
   Console release prerequisites.
